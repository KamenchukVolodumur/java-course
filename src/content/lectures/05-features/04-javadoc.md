## Javadoc

**Javadoc** — спеціальні коментарі `/** ... */`, які пишуть безпосередньо перед оголошенням класу, інтерфейсу, методу, поля чи конструктора. Інструмент `javadoc` з JDK обробляє їх і генерує HTML-документацію — саме так створено [документацію стандартної бібліотеки](https://docs.oracle.com/en/java/javase/21/docs/api/).

Навіщо документувати код:

1. **Підказки в IDE.** IntelliJ IDEA, Eclipse і VS Code показують Javadoc під час автодоповнення й на наведення курсора.
2. **Генерування документації.** HTML-сторінки публікують разом із бібліотекою, а в Maven Central поруч з JAR кладуть `-javadoc.jar`.
3. **Підтримуваність.** Документований публічний API легше використовувати й змінювати, не ламаючи очікувань користувачів.

```java
/**
 * Абстрактна математична матриця.
 * <p>
 * Конкретні реалізації визначають спосіб зберігання елементів:
 * {@link DenseMatrix} зберігає всі елементи, {@link SparseMatrix} — лише ненульові.
 */
public abstract class Matrix { }
```

Перше речення коментаря — **короткий опис** (summary): він потрапляє в таблиці зведень документації, тому має бути змістовним і самодостатнім. Решта — детальний опис. Текст коментаря — це HTML: абзаци відокремлюють `<p>`, списки — `<ul>`/`<li>`.

## Блокові теги

Блокові теги починаються з `@` на початку рядка і йдуть після опису:

| Тег | Призначення |
| --- | --- |
| `@param name опис` | параметр методу або конструктора |
| `@param <T> опис` | параметр типу (generic) |
| `@return опис` | значення, яке повертає метод |
| `@throws Тип опис` | виняток, який може кинути метод (синонім `@exception`) |
| `@see посилання` | «Див. також» |
| `@since версія` | з якої версії елемент існує |
| `@deprecated пояснення` | елемент застарів (разом з анотацією `@Deprecated`) |
| `@author`, `@version` | автор і версія (для класів) |

```java
/**
 * Знімає кошти з рахунку.
 *
 * @param amount сума до зняття; має бути додатною
 * @return залишок після операції
 * @throws IllegalArgumentException якщо {@code amount <= 0}
 * @throws InsufficientFundsException якщо на рахунку бракує коштів
 * @see #deposit(BigDecimal)
 * @since 1.2
 */
public BigDecimal withdraw(BigDecimal amount) { ... }

/**
 * Повертає перший елемент колекції, що задовольняє умову.
 *
 * @param <T> тип елементів
 * @param items колекція для пошуку
 * @param condition умова
 * @return знайдений елемент або порожній {@code Optional}
 */
public static <T> Optional<T> findFirst(Iterable<T> items, Predicate<? super T> condition) { ... }
```

> [!TIP]
> Документуйте **контракт**, а не реалізацію: що метод приймає (допустимі значення, чи можна `null`), що повертає (чи може бути порожнім), які винятки кидає і чи потокобезпечний. Коментар «повертає ім'я» до методу `getName()` нічого не додає.

## Вбудовані теги

Вбудовані теги пишуть у фігурних дужках усередині тексту:

| Тег | Призначення |
| --- | --- |
| `{@code текст}` | код у тексті, моноширинним шрифтом; HTML-символи не інтерпретуються |
| `{@literal текст}` | текст як є, без інтерпретації HTML |
| `{@link Тип#метод(параметри)}` | посилання на інший елемент API |
| `{@linkplain Тип#метод текст}` | те саме, але звичайним шрифтом |
| `{@value Тип#КОНСТАНТА}` | значення константи |
| `{@inheritDoc}` | вставити документацію перевизначеного методу |
| `{@snippet ...}` | блок прикладу коду (Java 18) |

Формат посилань: `Клас`, `Клас#метод`, `Клас#метод(int, String)`, `#метод` (у поточному класі), `пакет.Клас#поле`.

## Спецсимволи

Текст Javadoc — це HTML, тож символи `<`, `>` і `&` треба екранувати (`&lt;`, `&gt;`, `&amp;`) або обгорнути в `{@code ...}`, усередині якого їх писати можна:

```java
/**
 * Повертає значення &lt; 1.
 * Еквівалентно {@code x < 1 && y > 0}.
 * Повертає {@code List<String>}, а не масив.
 */
```

## Приклади коду

Для багаторядкових прикладів від Java 18 використовують тег `{@snippet}`. Він зберігає відступи, підсвічує синтаксис і не вимагає екранування:

```java
/**
 * Обчислює середнє арифметичне.
 *
 * {@snippet :
 * double[] data = {1, 2, 3};
 * double avg = Statistics.mean(data);   // 2.0
 * }
 */
public static double mean(double[] data) { ... }
```

У старшому коді трапляється конструкція `<pre>{@code ... }</pre>` з тією самою метою.

## Успадкування документації

Якщо метод перевизначає метод надкласу чи реалізує метод інтерфейсу й не має власного коментаря, Javadoc **автоматично** копіює документацію батьківського методу. Щоб доповнити її, використовують `{@inheritDoc}`:

```java
/**
 * {@inheritDoc}
 * <p>
 * Ця реалізація працює за O(1).
 */
@Override
public int size() { return count; }
```

## Коментарі в Markdown (Java 23)

Від Java 23 (JEP 467) документацію можна писати в **Markdown**, використовуючи коментарі `///`. Блокові й вбудовані теги працюють так само, а посилання записують у квадратних дужках:

```java
/// Повертає більший з двох аргументів.
///
/// - якщо аргументи рівні, повертається `a`;
/// - `null` не допускається.
///
/// @param a перше значення
/// @param b друге значення
/// @return більше значення
/// @see [Math#max(int, int)]
public static <T extends Comparable<T>> T max(T a, T b) { ... }
```

## Документація пакетів і модулів

* Опис **пакета** пишуть у файлі `package-info.java` (Javadoc перед оголошенням `package`).
* Опис **модуля** — у Javadoc перед оголошенням у `module-info.java`.
* Загальний огляд усього проєкту — у файлі `overview.html`, який передають опцією `-overview`.

## Генерування документації

```bash
javadoc -d docs -sourcepath src/main/java -subpackages pl.mini      # HTML у каталог docs
mvn javadoc:javadoc                  # target/reports/apidocs
mvn javadoc:jar                      # *-javadoc.jar для публікації
./gradlew javadoc                    # build/docs/javadoc
```

Перевірка **doclint** (увімкнена за замовчуванням) повідомляє про некоректний HTML, відсутні `@param`/`@return` і неіснуючі посилання. На серверах CI її часто роблять суворою, щоб недокументований публічний API не потрапляв у релізи: `javadoc -Xdoclint:all,-missing`.
