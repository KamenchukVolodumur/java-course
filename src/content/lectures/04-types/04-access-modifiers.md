## Рівні доступу

* **`public`** — доступ звідусіль. За замовчуванням публічні **члени інтерфейсів** (методи й константи).
* **`protected`** — доступ у межах **пакета** і з **підкласів** (зокрема з інших пакетів).
* *(без модифікатора)* **package-private** — доступ лише з класів **того самого пакета**. Це рівень за замовчуванням для **класів** і **членів класів**.
* **`private`** — доступ лише в межах **верхньорівневого класу**, у якому оголошено член (включно з його вкладеними класами).

| Модифікатор | Той самий клас | Той самий пакет | Підклас в іншому пакеті | Усі інші |
| --- | --- | --- | --- | --- |
| `public` | ✅ | ✅ | ✅ | ✅ |
| `protected` | ✅ | ✅ | ✅ | ❌ |
| *(без модифікатора)* | ✅ | ✅ | ❌ | ❌ |
| `private` | ✅ | ❌ | ❌ | ❌ |

Верхньорівневий тип може бути лише `public` або package-private. Члени й вкладені типи можуть мати будь-який з чотирьох рівнів.

```java
package pl.mini.bank;

public class Account {
    public String owner;            // усім
    protected long balance;         // пакету й підкласам
    String branch;                  // лише пакету pl.mini.bank
    private String pin;             // лише класу Account

    private static class Audit { }  // вкладений приватний тип
}

class Helper { }                    // package-private: невидимий поза pl.mini.bank
```

## Особливості protected

`protected` у Java **ширший**, ніж можна очікувати: член видно не лише підкласам, а й **усьому пакету**. Крім того, підклас з **іншого пакета** може звертатися до `protected`-члена лише через посилання власного типу (або його підтипу), а не через довільний об'єкт надкласу:

```java
package pl.mini.bank.premium;

public class PremiumAccount extends pl.mini.bank.Account {
    void demo(PremiumAccount other, pl.mini.bank.Account plain) {
        this.balance = 0;           // OK
        other.balance = 0;          // OK: той самий тип, що й підклас
        // plain.balance = 0;       // ПОМИЛКА: balance has protected access in Account
    }
}
```

## private і вкладені класи

Приватні члени доступні всьому коду **всередині верхньорівневого класу**, включно з вкладеними класами, і навпаки: зовнішній клас бачить приватні члени вкладених. Від Java 11 JVM напряму підтримує таких «сусідів по гнізду» (nestmates), без допоміжних синтетичних методів.

```java
public class Pizza {
    private final int size;

    private Pizza(Builder b) { this.size = b.size; }   // приватний конструктор

    public static class Builder {
        private int size;
        public Pizza build() { return new Pizza(this); }   // OK: доступ до private зсередини Pizza
    }
}
```

## Модулі — інкапсуляція на рівні бібліотек

Публічний клас видно всім, хто має його на classpath. Щоб приховати внутрішні пакети бібліотеки, використовують **модулі** (Java 9): файл `module-info.java` вирішує, які пакети модуль **експортує**. Публічні класи неекспортованих пакетів недоступні ззовні, навіть через рефлексію.

```java
module pl.mini.bank {
    exports pl.mini.bank.api;            // публічний API
    // pl.mini.bank.internal не експортується: його public-класи видно лише всередині модуля
}
```

Детальніше — на сторінці «Модулі й завантажувачі класів».

> [!TIP]
> Правило мінімальних прав: починайте з `private` і розширюйте видимість лише тоді, коли це справді потрібно. Поля майже завжди `private`. Класи, які не є частиною API, робіть package-private. Що менше видно ззовні, то вільніше можна змінювати реалізацію.
