## Обов'язкова ініціалізація

Компілятор Java вимагає, щоб кожна **локальна** змінна отримала значення до першого читання (*definite assignment*). Він аналізує всі шляхи виконання: якщо хоча б на одному змінну може бути прочитано без присвоєння, це помилка компіляції. Правило не стосується **полів** класу й елементів **масивів**: вони автоматично заповнюються значеннями за замовчуванням.

```java
int x;
// System.out.println(x);        // ПОМИЛКА: variable x might not have been initialized

int y;
if (flag) y = 1; else y = 2;
System.out.println(y);           // OK: присвоєно на всіх шляхах

int z;
if (flag) z = 1;
// System.out.println(z);        // ПОМИЛКА: якщо flag == false, z не присвоєно

int[] ints = new int[2];
System.out.println(ints[1]);     // 0

class Test { int value; }
System.out.println(new Test().value);   // 0
```

## Значення за замовчуванням

Поля й елементи масивів ініціалізуються «нулями»:

| Тип | Значення |
| --- | --- |
| `byte`, `short`, `int`, `long` | `0` |
| `float`, `double` | `0.0` |
| `char` | `'\u0000'` |
| `boolean` | `false` |
| будь-який посилальний тип | `null` |

Окремого оператора на кшталт `default(T)` у Java немає. Для узагальненого типу `T` значенням за замовчуванням завжди є `null`, бо `T` — посилальний тип.

## Виведення типу: var

Від Java 10 тип **локальної** змінної можна не писати, якщо компілятор може вивести його з виразу ініціалізації. Змінна все одно має статичний тип: `var` — не динамічна типізація.

```java
var greeting = "Hello class";            // String
var i = 0;                               // int
var x = 0.15f;                           // float
var list = new ArrayList<Integer>();     // ArrayList<Integer>
var today = LocalDate.now().getDayOfWeek();   // DayOfWeek
for (var entry : map.entrySet()) { }     // Map.Entry<K, V>
try (var in = Files.newBufferedReader(path)) { }

// var empty;              // ПОМИЛКА: потрібна ініціалізація
// var nothing = null;     // ПОМИЛКА: тип null невідомий
// var arr = {1, 2};       // ПОМИЛКА: потрібен new int[]{1, 2}
// var f = x -> x + 1;     // ПОМИЛКА: лямбді потрібен цільовий тип
```

Обмеження:

* лише **локальні змінні** з ініціалізацією, змінні циклів і ресурси `try`, а також параметри лямбд (`(var a, var b) -> a + b`);
* не можна для полів, параметрів методів і типів результату.

> [!WARNING]
> `var list = new ArrayList<>();` виводить тип `ArrayList<Object>`: diamond `<>` без цільового типу не має з чого вивести параметр. Пишіть `new ArrayList<String>()` або оголошуйте тип явно. Загалом `var` доречний, коли тип очевидний з правої частини, і шкодить, коли його треба вгадувати: `var result = service.process(data);`.

## final і effectively final

Змінну з модифікатором `final` можна присвоїти **лише один раз**. Для посилань це означає, що змінна завжди вказує на той самий об'єкт, хоча сам об'єкт може змінюватися.

```java
final int max = 100;
// max = 200;                       // ПОМИЛКА

final List<String> names = new ArrayList<>();
names.add("Ola");                   // OK: змінюється об'єкт, а не посилання
// names = new ArrayList<>();       // ПОМИЛКА

final String label;                 // final можна присвоїти пізніше, але рівно один раз
label = flag ? "так" : "ні";
```

Змінна, яку ніде не змінюють після ініціалізації, вважається **effectively final** навіть без ключового слова. Лише такі локальні змінні можуть захоплювати лямбди й анонімні класи (сторінка «Функціональні інтерфейси»).

## Константи

Константи класу оголошують як `static final` і за конвенцією називають у стилі `UPPER_SNAKE_CASE`:

```java
public class Physics {
    public static final double G = 6.674e-11;
    public static final int MAX_ITERATIONS = 1_000;
    private static final String PREFIX = "phys-";
}
```

Якщо константа має примітивний тип або `String` і ініціалізована константним виразом, це **константа часу компіляції**: компілятор підставляє її значення прямо в місця використання (навіть в інших класах). Тому зміна значення такої публічної константи в бібліотеці вимагає перекомпілювати код, що її використовує.

## Область видимості

Локальна змінна видима від оголошення до кінця блоку `{ }`, у якому її оголошено. На відміну від C++, у вкладеному блоці **не можна** оголосити локальну змінну з тим самим ім'ям, що й у зовнішньому (затінення локальних змінних заборонене). Затіняти можна лише поля класу.

```java
class Counter {
    private int count;

    void increment(int count) {          // параметр затіняє поле
        this.count += count;             // this.count — поле, count — параметр
    }

    void demo() {
        int x = 1;
        {
            // int x = 2;                // ПОМИЛКА: variable x is already defined
            int y = 2;
        }
        // System.out.println(y);        // ПОМИЛКА: y поза областю видимості
        for (int i = 0; i < 3; i++) { }
        for (int i = 0; i < 3; i++) { }  // OK: попереднє i вже не видиме
    }
}
```

> [!TIP]
> Оголошуйте змінну якомога ближче до першого використання і з найменшою можливою областю видимості. Так код легше читати, і випадково використати змінну не там неможливо.
