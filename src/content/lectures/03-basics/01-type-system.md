## Дві категорії типів

У Java є дві категорії типів, які визначають, як дані зберігаються в пам'яті та як із ними поводиться мова:

* **примітивні типи** (primitive types);
* **посилальні типи** (reference types).

Набір примітивних типів **фіксований**: їх рівно вісім, і створити власний примітивний тип неможливо. Кожен тип, який оголошує програміст, — клас, інтерфейс, enum, record, масив — є посилальним.

## Примітивні типи

Змінна примітивного типу зберігає **саме значення**. Кожна змінна має власну незалежну копію даних. Локальні змінні примітивних типів живуть у кадрі стеку методу, а поля примітивних типів — усередині об'єкта, якому належать.

**Примітивні типи:**

* цілочисельні: `byte`, `short`, `int`, `long`;
* дробові: `float`, `double`;
* символьний: `char`;
* логічний: `boolean`.

## Посилальні типи

Змінна посилального типу зберігає **посилання** (адресу) на об'єкт, що розміщений у **купі** (heap). Сама змінна (наприклад, локальна) лежить у стеку, але вказує на дані деінде.

**Вбудовані посилальні типи:**

* `String`;
* `Object` — спільний предок усіх класів;
* масиви (`int[]`, `String[]`);
* класи-обгортки примітивів (`Integer`, `Double`, `Boolean` …).

**Посилальні типи, які оголошує програміст:**

* `class` (зокрема `record`);
* `interface` (зокрема анотації `@interface`);
* `enum`.

## Семантика присвоєння

Те, що копіює оператор присвоєння `=`, залежить від категорії типу.

### Примітивні типи

Присвоєння змінної примітивного типу створює **повну копію значення**. Змінні далі незалежні: зміна однієї не впливає на іншу.

```java
int a = 3;
int b = a;        // b отримує КОПІЮ значення
b = 10;

System.out.println(a);   // 3
System.out.println(b);   // 10
```

```text
стек
┌─────────┐
│ a │  3  │
├─────────┤
│ b │ 10  │
└─────────┘
```

### Посилальні типи

Присвоєння змінної посилального типу копіює лише **посилання** (адресу об'єкта). Обидві змінні вказують на **той самий об'єкт** у пам'яті. Зміна даних об'єкта через одну змінну видна через іншу.

```java
class Person {
    String name;
    int age;
}

Person alice = new Person();
alice.name = "Alice";
alice.age = 16;

Person bob = alice;        // КОПІЯ ПОСИЛАННЯ: той самий об'єкт

bob.name = "Bob";
bob.age = 18;

System.out.println(alice.name + ", " + alice.age);   // Bob, 18
System.out.println(bob.name + ", " + bob.age);       // Bob, 18
```

```text
     стек                          купа
┌───────────────┐
│ alice │ ●─────┼──────┐
├───────────────┤      ▼
│ bob   │ ●─────┼──► ┌──────────────────┐
└───────────────┘    │ Person           │
                     │ name: "Bob"      │
                     │ age:  18         │
                     └──────────────────┘
```

Щоб отримати незалежну копію об'єкта, її треба створити явно: конструктором копіювання (`new Person(other)`), методом-фабрикою або, для колекцій, `new ArrayList<>(list)`, `List.copyOf(list)`.

> [!TIP]
> Найпростіший спосіб уникнути несподіванок спільного змінюваного стану — **незмінні об'єкти** (усі поля `final`, без сетерів, наприклад records). Посилання на незмінний об'єкт можна вільно передавати й копіювати: змінити його ніхто не зможе.

## Значення null

* Змінна **примітивного типу** не може бути `null`: вона завжди містить конкретне значення (поле `int` за замовчуванням дорівнює `0`). Присвоєння `null` — помилка компіляції.
* Змінна **посилального типу** може містити `null`: це означає, що вона не вказує на жоден об'єкт. Виклик методу чи звертання до поля через `null` кидає `NullPointerException`.

```java
int count = 0;
// count = null;          // ПОМИЛКА КОМПІЛЯЦІЇ: incompatible types: <null> cannot be converted to int

Integer boxed = null;     // OK: Integer — посилальний тип
Person p = new Person();
p = null;                 // OK: p більше не вказує на об'єкт
// p.name = "x";          // NullPointerException під час виконання
```

Щоб виразити «значення може бути відсутнє» для числа, використовують обгортку (`Integer`), спеціальне значення (`-1`, `OptionalInt.empty()`) або `Optional<T>` для результатів методів (сторінка «null і Optional»).

## Значення за замовчуванням

Поля класу й елементи масиву автоматично отримують значення за замовчуванням: `0` для чисел, `'\u0000'` для `char`, `false` для `boolean` і `null` для посилань. **Локальні змінні** значень за замовчуванням не мають: компілятор вимагає їх ініціалізувати перед першим читанням.

```java
class Counter {
    int value;          // 0
    String label;       // null
}

void method() {
    int x;
    // System.out.println(x);   // ПОМИЛКА: variable x might not have been initialized
}
```

## Передавання параметрів у методи

У Java параметри **завжди** передаються **за значенням**. Інших режимів (за посиланням) у мові немає. Але для двох категорій типів «значення» означає різне:

* для **примітивних типів** у метод потрапляє **копія значення**: зміни параметра всередині методу не впливають на змінну викликача;
* для **посилальних типів** у метод потрапляє **копія посилання**: і оригінал, і копія вказують на той самий об'єкт у купі. Зміна *стану* об'єкта (його полів) буде видна поза методом.

```java
public class Params {
    public static void main(String[] args) {
        int n = 1;
        modifyPrimitive(n);
        System.out.println(n);                       // 1: метод змінив лише копію

        Person person = new Person();
        person.name = "Alice";
        modifyReference(person);
        System.out.println(person.name);             // Bob: метод змінив спільний об'єкт

        replaceReference(person);
        System.out.println(person.name);             // Bob: нове посилання лишилося в методі
    }

    static void modifyPrimitive(int value) {         // value — копія n
        value = 100;
    }

    static void modifyReference(Person p) {          // p — копія посилання
        p.name = "Bob";                              // змінюємо об'єкт, на який вона вказує
    }

    static void replaceReference(Person p) {
        p = new Person();                            // змінює лише локальну копію посилання
        p.name = "Charlie";
    }
}
```

* `modifyPrimitive` працює з повністю незалежною копією числа, зміни назовні не видно.
* `modifyReference` отримує копію посилання на той самий об'єкт `Person`, тож зміна поля `name` — постійна.
* `replaceReference` присвоює параметру новий об'єкт. Це змінює лише локальну копію посилання; змінна `person` у `main` і далі вказує на старий об'єкт.

> [!NOTE]
> Метод не може «повернути» значення через параметр. Якщо треба повернути кілька результатів, повертають record (`record MinMax(int min, int max)`), масив або об'єкт, який метод заповнює.

## Стек і купа

| | Стек (stack) | Купа (heap) |
| --- | --- | --- |
| Що зберігає | кадри викликів: параметри, локальні змінні (примітиви й посилання) | усі об'єкти й масиви |
| Хто керує | автоматично: кадр зникає після повернення з методу | збирач сміття |
| Кому належить | окремий стек для кожного потоку | спільна для всіх потоків |
| Розмір | невеликий (`-Xss`, зазвичай 512 КБ – 1 МБ) | великий (`-Xmx`) |
| Помилка переповнення | `StackOverflowError` | `OutOfMemoryError` |

> [!NOTE]
> «Усі об'єкти — у купі» — це модель мови. Оптимізатор JIT може не створювати об'єкт, який не виходить за межі методу (**escape analysis**), і розкласти його поля в регістри. Програміст цього не бачить: семантика лишається тією самою.
